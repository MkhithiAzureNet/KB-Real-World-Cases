# Contribution Guidelines

- Place each document in the most relevant category and subcategory.
- Prefer concise, reusable documentation based on observed scenarios and verified procedures.
- Use the case template when documenting troubleshooting work; adapt it when another format better fits the subject.
- Separate confirmed facts from assumptions, and include validation steps and relevant limitations.
- Use Markdown and descriptive, hyphenated filenames.
- Never publish credentials, tokens, private keys, personal information, customer data, or sensitive infrastructure details. Redact or replace them with clearly fictional examples.
- Keep security material focused on authorized administration, defense, remediation, and safe validation.
- Link to authoritative vendor references where they add useful context.
- Update relevant folder indexes when adding new material.
